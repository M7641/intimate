# Bespoke to product

If I was leading a transition from bespoke to Product.

1. I would do it incremnetally, I would look to identify all the shared problems we are working on and start developing their abstracted form. A customer wants to know their demand next month -> Forecast. A customer wants to know saftey stock -> Error distributions. 
2. With shared blocks defined, you could have resourced a foreast team to develop the tooling to radically speed up the deployment of the forecast aspect of a project. With a clearly maintained API and was more about provideing to the tools to help with bespoke forecasts. Furuture customers, would be on the box version of the forecast.
3. Religioulgly defend APIs of the shared blocks. If someone wants to add one more feature that would only benefit one customer and does not fit into the broader problem, then block and ask them to do a bospoke implementation in that case.
